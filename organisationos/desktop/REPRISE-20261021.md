Le client Desktop n'est pas le DocumentServer Linux reçu. Aucun PE Desktop
OrganisationOS n'a été construit, signé Windows ou proposé au téléchargement.
La contrainte actuelle est une chaîne Windows MSVC/Qt absente des moyens autorisés.

Recherche effectuée : les cinq hôtes autorisés sont Linux ; aucun cl.exe, qmake
Windows, ISCC ou Wine utilisable sur DEV. Les passations Buddy et les inventaires
locaux retrouvés ne désignent pas de builder Windows ; THE-141 concernait

recherche ne prouve pas l'absence de toute machine non inventoriée. Le poste
10.9.5.90 est exclu : il est réservé à la réception, pas à la compilation.

Prérequis concrets : builder Windows x64 dédié et accès authentifié autorisé,
Visual Studio 2019 avec compilateur MSVC v142 x64 (défaut de la recette épinglée),
Windows SDK compatible, Qt MSVC x64 avec qmake/windeployqt, Python, Git, Node/npm,
7-Zip et Inno Setup. Prévoir 150 Gio libres dont 40 Gio de réserve pour ce lot
(estimation de planification OrganisationOS, pas minimum publié amont). Exécuter
Test-Builder.ps1 en lecture seule et figer versions, empreintes et provenance.

0ef79ad22cc1b2e9364e6a165d1ee00f9348b46f6bb94615a48ed402145f741a,
reçue sur .20 : son identifiant Git blob correspond exactement à l'arbre amont.
Aucune signature indépendante du fournisseur n'est revendiquée. Le script
prepare-cef.py vérifie le commit build_tools, le fichier amont et l'archive;
il fixe l'URL au commit et ajoute un refus d'extraction si le SHA256 diffère.
Il refuse un cache de construction CEF déjà présent. Sur le builder dédié :

    python prepare-cef.py --build-tools C:\build\build_tools --core C:\build\core --archive C:\inputs\cef_binary.7z --check-only

Après préflight, retirer --check-only pour préparer la dépendance. La préparation
ne compile ni n'exécute CEF. Vérifier ensuite les notices incluses dans l'archive
avant distribution. Le contrôle Python et le refus d'une source modifiée ont été
exercés sur Linux; le parcours Windows reste à recevoir.
