# Point de reprise Desktop — 21 octobre 2026

Le client Desktop n'est pas le DocumentServer Linux reçu. Aucun PE Desktop
OrganisationOS n'a été construit, signé Windows ou proposé au téléchargement.
La contrainte actuelle est une chaîne Windows MSVC/Qt absente des moyens autorisés.

Recherche effectuée : les cinq hôtes autorisés sont Linux ; aucun cl.exe, qmake
Windows, ISCC ou Wine utilisable sur DEV. Les passations Buddy et les inventaires
locaux retrouvés ne désignent pas de builder Windows ; THE-141 concernait
PowerShell sous Linux. Les recherches GitHub de l'organisation pour
« self-hosted windows » et « vcvarsall » n'ont donné aucun résultat indexé. Cette
recherche ne prouve pas l'absence de toute machine non inventoriée. Le poste
10.9.5.90 est exclu : il est réservé à la réception, pas à la compilation.

Prérequis concrets : builder Windows x64 dédié et accès authentifié autorisé,
Visual Studio 2019 avec compilateur MSVC v142 x64 (défaut de la recette épinglée),
Windows SDK compatible, Qt MSVC x64 avec qmake/windeployqt, Python, Git, Node/npm,
7-Zip et Inno Setup. Prévoir 150 Gio libres dont 40 Gio de réserve pour ce lot
(estimation de planification OrganisationOS, pas minimum publié amont). Exécuter
Test-Builder.ps1 en lecture seule et figer versions, empreintes et provenance.

La fermeture tierce n'est pas encore complète : build_tools au commit
a9f9895b172b09595abcafe85d56fab163f9ecb7 choisit la branche CEF 5414/win_64 mais
référence une archive sur la branche flottante master de
ONLYOFFICE-data/build_tools_data. Il faut remplacer cette résolution par un
commit et un SHA256 reçus avant de compiler. La version Qt dépend de QT_DEPLOY,
non d'un pin fourni par défaut. Ne pas prétendre disposer d'une recette fermée.
Les pins des six composants Desktop sont dans sources.lock.json ; trois seulement
ont été récupérés. La marge DEV (~2,7 Gio au-dessus des 40 Gio) interdit de
rapatrier ou reconstruire tout le client ici.

Raccordement préparé dans Portal : portal:login seulement après /auth/me natif,
portal:logout après invalidation native réussie, open:document vers la route
Documents Office autorisée ; même provider « organisationos », origine propre
à chaque portail. Le routeur de module conserve l'exigence Documents actif.
Les tests de ces commandes prouvent le contrat JavaScript, pas l'exécution CEF.
La suppression d'un cloud depuis le menu Desktop ne prouve pas l'invalidation
serveur d'une session : ce cas demeure à recevoir dans le vrai client.

Suite dès que le builder est disponible : fermer les outils/CEF, récupérer les
pins manquants, appliquer le branding depuis les sources sans retirer les notices,
compiler deux sorties, inventorier PE/dépendances/signatures, puis emballer un
moteur commun et les deux profils d'organisation. Le catalogue privé ne doit
publier aucun faux installateur en attendant ce résultat.
