# Exécution du serveur construit

Candidat de qualification, non reçu en production. La base officielle `onlyoffice/documentserver:10.0.0` est épinglée par digest. Elle fournit le système, les dépendances, le démarrage amont et le seul outil JSON de configuration `npm/json`, conservé séparément des moteurs documentaires. Son répertoire applicatif est supprimé dans la nouvelle couche puis remplacé intégralement par les sorties du fork : DocService, FileConverter, outils, bibliothèques, SDK et interfaces. La provenance finale doit enregistrer les empreintes des exécutables effectivement exécutés et le digest de la nouvelle image. L'image officielle seule ne représente jamais notre fork.

Le contexte de construction doit contenir `documentserver/` issu de la construction vérifiée, sans fichiers `.git`, les fichiers `configuration/default.json` et `configuration/production-linux.json` provenant du composant `server/Common/config` épinglé, les notices amont conservées, `provenance.json`, `source.html`, et le lanceur de ce répertoire. Les polices et thèmes sont générés par les outils du fork pendant la construction. Les services d'exemple, Metrics, WOPI et panneau d'administration restent désactivés. L'avertissement amont concernant le module natif optionnel Metrics ne peut ainsi être ignoré pour un Metrics activé ultérieurement.

Un secret JWT aléatoire propre à l'instance doit être fourni au démarrage dans `/run/secrets/organisationos-office-jwt`, fichier root 0400 monté en lecture seule ; aucun secret de production n'entre dans le contexte de construction. Son affectation au connecteur utilise le coffre natif. Les données/cache/logs sont isolés par installation et conservés lors du retrait du code.

L'édition communautaire amont épinglée utilise `memoryConnector` et `taskqueueMemory`, sans persistance SQL de session entre redémarrages. Ne pas ajouter PostgreSQL/RabbitMQ sur la base d'une documentation d'ancienne version. L'admission durable dans la GED reste indépendante ; une fermeture préparée doit demander la sauvegarde puis attendre son reçu canonique. Une coupure brutale ne doit pas être présentée comme ayant enregistré les modifications non confirmées. Les comportements réels de reprise restent à qualifier.

Le réseau de qualification n'expose que le port de navigateur local ; aucune GED réelle n'est montée. Avant production, qualifier la route TLS, les callbacks authentifiés, l'accès aux seules URL documentaires admises, les limites mémoire/disque, l'arrêt propre, la reprise et les refus d'accès. La levée éventuelle de l'interdiction des IP privées requiert un filtrage réseau effectif vers la seule instance autorisée ; les adresses de métadonnées restent interdites.

La première qualification de démarrage a détecté un écart de schéma entre les fichiers de configuration de la base officielle et ceux du composant server épinglé (`aiSettings.proxy`). Les configurations applicatives sont donc remplacées par celles des mêmes sources que les exécutables. Les paramètres d’instance et JWT restent injectés au démarrage.

Le lanceur DocService publie un identifiant aléatoire non secret à chaque démarrage effectif, y compris après relance par supervisor : `/web-apps/organisationos/runtime.json`, explicitement sans cache. Les sessions GED doivent être liées à cet identifiant et refuser de continuer automatiquement une salle provenant d’un démarrage précédent. Un contrôle de santé réussi ne prouve pas la conservation d’une session en mémoire. Le marqueur ne contient ni credential ni identité d’employé. Sa récupération TLS depuis la destination du connecteur et le comportement de reprise restent à qualifier dans l’adaptateur GED.

La [réception v2 du 21 octobre 2026](reception-v2-20261021.json) identifie l'image réellement exécutée et les empreintes de ses moteurs : édition clavier DOCX/XLSX/PPTX, six retours authentifiés, rapprochement de leur preuve avec le fichier original et déduplication de la fermeture. Cette réception isolée ne vaut pas installation en production ni enregistrement canonique GED. Les sorties précédentes et les refus de réception restent conservés dans les preuves opérateur.
